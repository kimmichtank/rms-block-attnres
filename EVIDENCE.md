# Evidence and claim ledger

The initial audit snapshot was taken on 2026-09-27; later read-only audits captured completion of the three original 4B runs and the three 512M-parameter runs. This archive reports what the files establish, not what run names suggest. No remote training or checkpoint mutation was performed for this release.

Start with the [evidence directory guide](evidence/README.md), [machine-readable claims](evidence/claims.json), [generated numbers](results/derived.json), [tables](results/tables.md) and the [source manifest](evidence/source-manifest.json). The source manifest identifies original artifacts by SHA256 and neutral IDs. For small-model metrics the original JSON contents are preserved; configs/manifests are path-redacted. Large-model CSVs retain the original log hash, source ID and line number. Public-file hashes are separate from original-file hashes. Original private paths are intentionally not included.

## Small-model audit details

All four 57M runs have 56,836,352 trainable parameters, 9500 updates, 999,038,753 effective training labels and 4,995,188 test labels. All three 157M runs have 157,433,856 parameters, 74,992 updates, 3,200,000,000 labels and 5,000,000 test labels. All three runs conventionally called “450M” have 512,416,576 parameters, 234,011 updates, 10,000,000,000 labels and 5,000,000 test labels. Parameters were randomly initialized; publisher pretrained/chat weights were never loaded.

Full+RMS 57M used one H100 MIG 3g.40gb instance with micro-batch 64 and accumulation 4. The other 57M runs used four H100 80GB GPUs with micro-batch 64 and accumulation 1. All used global batch 256, matching input fingerprints, permutation seed and schedule. This does not make floating-point reduction order identical. The Full+RMS log contains 9865 rows but 9500 unique steps after resume; 365 repeated step records are deduplicated by last occurrence, not counted as extra data. Its final COMPLETE/test agree with the last training step. The 157M and 512M formal runs use four H100 80GB GPUs, micro-batch 16, global batch 64.

Data uses normalized-text exact deduplication and deterministic hash splits. Near-duplicate removal beyond the upstream dataset was not performed. No downstream benchmark result is claimed. Public corpus recipes preserve ordering rules; metadata hashes containing local paths/timings will change after portability edits even when token sequences match. The 157M indexed token and index hashes permit content-level verification.

## Diagnostic population and precision

The 57M diagnostics use 64 sampled test chunks/27,087 valid positions; 157M uses 32 chunks/16,281 positions, one batch each. A chunk is not necessarily an independent document. Embeddings are excluded from residual-output statistics. The same selected indices are used for all three variants within each size. Checkpoint hashes and indices are in each diagnostic manifest.

Formula/native aggregate and backbone replay differences are zero in the saved checks. Correlations use at most 4096 positions per source/read, then at most 500,000 pooled triples. Source magnitudes recur at multiple reads. These are descriptive dependent samples, not 500,000 independent observations.

Counterfactual scales each member of a just-completed group, one at a time, freezes all other outputs and recomputes the next aggregator. The last block's final read is recorded separately and excluded from the headline `next_sublayer` summary. Relative RMS is the per-token RMS of the representation difference divided by baseline representation RMS, then summarized over positions/sources. Alpha change is total variation over source-softmax probabilities. The raw CSVs retain scale, read kind, member index and metric. Small nonzero RMS Block tails are compatible with epsilon/finite precision; their exclusive attribution to one cause was not separately tested.

The historical diagnostic code's multi-batch summary merge is not an exact pooled quantile calculation. It does **not** affect the archived single-batch results. The public entry point rejects multiple batches rather than reporting averaged quantiles as pooled medians.

## Limits of the audit

The 4B runs share the same indexed DCLM input and cache description, but the original download revision and exact public reconstruction of that preprocessed shard are unverified. The release provides the model config, patch, tokenizer provenance and launch parameters, not a false one-command guarantee. Comparing panels also changes backbone, tokenizer, context, data and training horizon. No scaling law or pure size effect is established.

Neither 157M nor 4B has Full+RMS. No archived Full+RMS checkpoint counterfactual is claimed. Full+RMS reuses an affine Key norm and includes the embedding, whereas RMS Block uses a non-affine norm only for completed sublayer groups; the existing four variants are useful controls, but not a perfectly isolated 2×2 factorial.
